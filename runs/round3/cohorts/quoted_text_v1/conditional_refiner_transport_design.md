Overflow-only routing is preferable here to always using a planner loop. It retains existing small-input behavior, fixtures, latency, and one-call accounting while changing only the demonstrated failing case. Always using the loop would create additional model interactions for every refinement and a larger comparison change, with no evidence that small inputs need it. Both routes must remain labeled in archived jobs and fresh comparison reports. A new cohort must use the same frozen implementation across arms; the failed cohort cannot be repaired in place and treated as an uninterrupted success.

Use one generic scoped-backend protocol for overflow execution, e.g. `with backend.scope(budget=planner_budget) as child_backend`. It creates a child cancellation future and a `dataclasses.replace` context with that future, preserving config, archive identity, runner injection, sleep, jitter, and the global FIFO slots. Parent cancellation propagates one way to the child only if the parent is cancelled. Scope cleanup cancels and drains only the child's worker/model operations. Store the original explicit runner override separately: copying `self.runner` from the parent backend would copy a bound parent `ctx.run_process` and defeat child cancellation. With no explicit override, the new instance must bind the child context's runner. Test transports implement this same small protocol for overflow tests; do not add `isinstance` branches or silently skip cancellation for fakes. Existing small-input test transports never need to enter a scope.
