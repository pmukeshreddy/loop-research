# Review protocol for the registered comparison

This file assigns output keys and review responsibilities; it does not amend the committed predictions. The governing registration is `runs/round3/predictions.md` at commit `2ecab945810592a7b9e084c3d3c5dc8b00a4f20a`, SHA-256 `cec6bffde76d8a79aeac7c037dde65910e6fcac1927e899d63d8624582951f78`. Runtime source is `902abe33d06f64c426a65d55d5e600dd6d6a052a`. Use only local files. Preserve all raw archives and existing source/inputs/harnesses; do not rerun research, alter learned entries, or tune scores toward a prediction.

For every assigned completed arm, write LABEL.review.md, LABEL.review.json and LABEL.manual.json. Resolve the run from its console Watch live line or launcher record, never by guessing from glob order. Run the unchanged `runs/round2/audit.py LABEL RUN --output-dir runs/round3/cohorts/readable_controls_v1/audits` only after natural terminal completion. Verify the complete LABEL.archive_hashes.json from the launcher (b.processes.json receives terminal arm records before the final phase execution.json update). Inspect every final required cell for quote membership at every cited URL and semantic support, with separate coverage concerns. All Round 3 measurements use direct-readable-v1. Report every error/recovery; do not equate all trace error events with unique underlying failures.

Manual JSON uses source_commit, analysis_contract=answer-ready-v2, runs.LABEL.run_id, metrics, and semantic_review. Each metric has value (nonnegative integer or null), reason, and evidence=[{path,line optional,note,file optional}]. Every null needs a reason; every count needs evidence. Existing metrics.py accepts these additional count fields. No floating-point manual ratios are required. The final aggregator computes standard numeric ratios already supported by the tool.

Required metric keys for every B arm:

- S1_pre_answer_ready_validation (binary), S2_gap_exposed (binary), S2_supplementary_unique_urls, S3_quote_exception_blocks, S3_caught_printed_quote_failures. S4 is computed mechanically by the unchanged helper.
- V1_bare_quote_exception_blocks and V1_bare_quote_exception_blocks_conditional. The second is null if S3=0, else the raw V1. This intentionally measures only terminated quote-guard blocks; caught/printed failures remain separate S3 records. No broad diagnostic-completeness claim.
- D0_duplicate_candidate_groups; D1_reconciled_before_mutation_groups; D2_destructive_overwrite_groups; D3_unresolved_overwrite_groups. Also include D1_reconciled_before_mutation_groups_conditional, D2_destructive_overwrite_groups_conditional, and D3_unresolved_overwrite_groups_conditional: null if D0=0, else the raw count. Follow the registered candidate-set, support, mutation-order and first-mutation definitions precisely. D1/D2/D3 cannot exceed D0, and D3 cannot exceed D2. If unsure, preserve uncertainty with cited N/A, not a guessed zero.
- F1_failed_response_extraction_calls and F1_failed_response_extraction_calls_conditional. Bind exact failed-fetch values to actual extraction/verification subcall evidence inputs. A mere instructional sentinel mention or a failure-diagnosis call is excluded; instructions to ignore failures do not remove an actual failed response included in source evidence. Conditional is null if there are no failed fetches, else raw F1.
- R2_retained_download_reuse_blocks. Only substantive reuse of an earlier block's successful retained download/derived evidence, without fetching that URL again in the using block; count each block once. A same-block first extraction or length print does not count.

The parent will add independently derived raw-body/dedup count fields to a combined manual file while preserving original reviews: downloaded_raw_artifact_bytes, retained_text_instances, unique_text_hashes, whole_text_hash_dedup_readable_characters. These count distinct archived HTTP response body files (including retained failures/redirect bodies) and retained successful evidence strings exactly as registered. The parent also aggregates all automatic metrics, full root partitions and individual subcall sizes; reviewers should retain the audit's evidence rather than duplicate calculation needlessly.

Semantic review count names, to keep comparisons consistent: semantically_supported_required_cells; unresolved_semantic_cells; concurrent_affiliation_scope_concerns. Supported means the listed value is supported; separate scope concerns can overlap supported cells and must not be silently added to the unresolved-value count. State any established falsehood separately. Count actual reviewed cells and cite the per-cell inventory. Use concrete uncertainty, never mechanical zero issues as semantic proof.

Alias JSON, when needed, uses source_commit and aliases=[{field,variant,canonical,reason,evidence}]. Preserve raw identity differences. Cite source-based identity matches, not fuzzy guesses. The parent will combine only reviewed aliases and retain each source receipt.

For learning-enabled B1, also review every refine request, full candidate inventory, decisions, edit/decline, commit and timing; distinguish midtask delivery/use from finalizer-only edits. For frozen/B0 arms, verify no procedural learning occurred and preserve actual usage/outcome bookkeeping. Initial input parity and full six-control integrity will be audited separately after all six complete. Three repeats are not a statistical result; the final table must show every registered metric, each value, means, min–max ranges, defined-N, and strict absolute mean delta versus the larger within-arm range.
