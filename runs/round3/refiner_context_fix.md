# Complete-snapshot refinement transport

The third Round 3 cohort failed at an architectural boundary that lossless duplicate sharing cannot remove: `Refiner._plan_job` still called `CodexBackend.complete` once with the entire encoded observation. Its actual mid-task request contained 1,611,089 backend characters against the observed 1,048,576-character limit. The complete supplied logical payload was 3,027,914 characters, with 77 trajectory records, one full historical entry and all 46 occurrences in three candidate groups. One attempt failed; the previously fixed permanent-error classification prevented retries. Exact input/schema/job identities and terminal error propagation are preserved in `cohorts/quoted_text_v1/A.failed_midtask_manifest.json` and the cohort reviews. This run had no final submission and supplies no completed quality or learning-benefit claim.

`refine.py` now compares the complete prospective backend prompt, including its 182-character transport instruction, with the evidenced provider limit. Inputs at or below that boundary use the existing direct path. Independent boundary checks cover one character below, exactly equal, and one character above. The original direct `INSTRUCTIONS` bytes remain unchanged (SHA-256 `72937f276d0bf1119d129f622123a744bb9bda388a4a1ab51fe17cc0bca4d3f6`). The branch is generic input transport selection, with no task, site, field or candidate selection.

Oversized observations use `refine_context.plan_context`. It archives the original complete logical JSON and strict schema, keeps that original JSON authoritative in the host, and exposes its complete value through a read-only `snapshot()` broker. An isolated Python worker receives a local copy in `context`, can restore the original with another snapshot read, inspect all fields through code, and make plain or structured sub-calls to the configured refinement model. It has no research, grader, answer-store or harness-write capability. Existing Seatbelt isolation is reused without expanding read roots. All model calls retain purpose `refine`; separate `Refiner context` events and a job-specific action journal keep these calls out of research-root, research-subcall and answer-ready measurements.

The small planner loop retains every model input, response, executed code block, complete stdout/stderr and final return. It does not use the inherited RLM formatter's 20,000-character cap. Its mutable Python variables are derived state; they cannot change the host snapshot. The original Proposal parsing, max-edits ceiling, candidate accounting and evidence validation remain before any harness edit. The context path also validates the exact original JSON schema, including its EvidenceRef enum, because it now submits a Python value rather than relying on the provider to enforce that final schema. A valid child pointer outside the original enum is rejected. Resuming a failed plan gets a new job ID and independent archive.

`CodexBackend.scope` supplies a child cancellation context, preserves the configured model/retry settings and explicit runner injection, propagates parent cancellation one way, closes admission before cancellation, and drains admitted calls. The default process runner is rebound to the child context. The context planner opts into full attempt prompt/response logging through a deep-copied child config; the parent's logging policy remains unchanged. This closes an independently reproduced gap where a 45-character failed-attempt reply disappeared after a successful retry. Transport stdout/stderr retain the existing backend policy; this fix does not claim complete raw subprocess-stream archival outside the replay recorder.

The broker opts into handler draining through `Server(..., drain_handlers=True)`. Child work is canceled before server exit, and complete handlers are then joined, including journal writes after model completion. A regression first demonstrated the old server exiting before those writes. The default research server behavior is unchanged.

The new iterative operation uses the configured `codex.timeout_s` (600 seconds in these runs) as one aggregate deadline and `rlm.max_iterations` (30) as its planner-turn ceiling. Its deadline budget adds no call-count allowance; individual backend retry configuration is unchanged. This is an explicitly stricter aggregate bound for the newly iterative transport, not a claim that it equals the old path's possible duration across repeated per-attempt deadlines. Research budgets, refinement scheduling, boundary application and finalization are unchanged. The researcher still decides when to request refinement. If the planner itself emits an oversized subsequent prompt or exhausts its deadline/turns, that remains a visible error; no content is silently removed.

The report renderer now labels the saved legacy `planner_prompt` as prospective and not dispatched for context transport, then reports actual linked attempt inputs. It distinguishes a durable dispatch with no completion from missing evidence. The archive-audit and saved-input replay compatibility corrections are a separate dependent change and must pass before any model replay or new research starts.

## Verification

- Inherited focused baseline: 57 passed. The first seven new integration tests all failed on the existing oversized dispatch before implementation.
- First context run: 6 passed and one deadline-exception mismatch; normalized the explicit operation timeout to `TimeoutError`. A separate drain test first hit a too-long test socket path; after correcting that fixture, it reproduced premature server exit, then passed with the opt-in drain.
- Expanded integration: 10 passed, including complete snapshot hash, unknown Unicode fields, complete historical entry metadata, distinct configured model roles, snapshot restoration after local mutation, host-read isolation, structured subcall use, full stdout/stderr beyond 20,000 characters, completed bindings after an error, strict schema/accounting failures, iteration exhaustion and hard worker deadline.
- Scoped backend: 67 focused tests passed after separate RED evidence for scope ownership and lost failed-attempt responses.
- Renderer: 3 passed after RED for prospective/actual confusion and interrupted attempt handling. One synthetic prompt-length fixture initially counted 20 instead of 21 characters; the archive-consistency check caught it and the fixture was corrected.
- Full offline suite on the integrated planner/scope source: **992 passed, one live test deselected, 123.90 seconds**. Independent targeted review: **70 passed, 14.62 seconds**.
- Independent scripted replay of the actual failed snapshot preserved its exact 3,027,914-character logical identity and original strict schema. Its scripted coordinator input was 4,926 characters and all three decisions passed host validation. This verifies transport and validation, not real-model semantic review or research success.

The failed cohort, every intermediate test log and the original proof-report bytes remain preserved. The next gate is a real-model saved-input replay on the final common source, followed by fresh A/SI, committed new predictions, B1, three frozen controls, three base controls and the separate explicit reuse check. No failed cohort or earlier POST_A may substitute for those runs.
