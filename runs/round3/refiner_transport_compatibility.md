# Overflow refinement archive/replay compatibility

The old replay recorder treated every process as one schema-constrained Codex invocation. Overflow planning launches an isolated Python process and makes several optional-schema model calls; backend scope also copies the context with `dataclasses.replace`, discarding dynamically attached counters and bypassing backend subclass guards. The old archive auditor counted refinement receipts but did not bind their actual action inputs, schemas or responses. These were compatibility defects in the audit/replay path, not new research failures.

The recorder now carries counters and guards in shared closure state. Exact command/model/web/purpose checks run at the actual process boundary. The worker must be the product's exact isolated refinement command/environment/contract; source context, full schema and independently computed evidence anchors are checked before worker or model dispatch. Full commands, optional stdin/schema and process results are retained. Python workers and Codex processes have separate counts; the all-route durable attempt count includes direct jobs and distinguishes the context-only count.

The audit exposes `refinement_transports` separately from research root/subcall statistics. It verifies preserved pre-routing wire/logical identity, complete context equality, full sidecar schema and manifest identity, actual action/backend input/schema/call IDs, retry order, retained failed responses, code/readiness/proposal linkage and strict schema/candidate accounting. It includes source hashes for jobs, all planner sidecars and linked receipts. The preserved monolithic `planner_prompt` is explicitly labeled pre-routing input and is never claimed to have been dispatched on the overflow route. An interrupted dispatched-only attempt retains its complete verified input but has null response, outcome and usage; a call missing both dispatch and completion evidence is rejected. Failed proposal validation is preserved as a failed outcome rather than misreported as archive corruption.

An offline check of all five current replay inputs found that the first two historical jobs predate evidence anchors. Their original schemas exactly equal the current pre-anchor base schema plus the original edit cap. They have neither representation metadata nor an evidence index. The explicit legacy contract preserves both schemas and hashes and records exactly three restrictive additions: an EvidenceRef enum, and references to it from Candidate/Decision evidence_refs items. Every other constraint remains identical; the final proposal must pass both original and current schemas and complete candidate accounting. Unrecognized old schemas or misleading metadata fail before dispatch. The remaining three cases have exact current schema/anchor identity. The first mismatch receipt remains unchanged, alongside the explicit contract receipt.
