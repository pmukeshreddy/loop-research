# Saved replay case admission

The failed `context_refiner_v1` preflight started five independent cases with a shared backend limit of four. All five case bodies began at 05:15:03 UTC. The four direct cases dispatched their first calls before the overflow worker requested its first model call. The overflow worker read the complete snapshot at 05:15:06.129422 and recorded model.start at 05:15:06.173879. It did not dispatch until 07:53:03.706271, 0.045478 seconds after the first direct call ended. The four first direct calls each recorded about 600 seconds of monotonic execution and timeout/DNS errors; all four later completed on retry. The overflow attempt recorded a PermissionError, then its existing aggregate deadline expired roughly two seconds after dispatch. The error origin remains unlocalized.

The long UTC interval includes machine sleep and is not presented as a measured monotonic queue duration. Detailed per-attempt errors and archived source hashes are retained in the diagnosis JSON; parent owns the independent sleep evidence and preservation. Nothing in the failed cohort was changed.

The helper previously used one executor thread per case. This started the fifth case's aggregate planner deadline while all four backend slots were already occupied by other cases. The change bounds outer case admission to `min(case_count, configured shared max_concurrent)` and records that value as `max_concurrent_cases` in execution.json. A queued case starts its replay/planner only after an admitted case returns. This is saved-preflight case admission only: source observations, schemas, candidates, call/retry budgets, timeout values and product refinement scheduling are unchanged. The bound does not promise zero contention among subcalls within the admitted cases, or resolve OS sleep/DNS/permission errors.

TDD evidence: the event-controlled five-case/four-slot test failed because the fifth case entered while the first four were held on release events. The second test failed on the absent admission metadata. After the change the fifth enters only after the released first case has ended, peak active cases is exactly four, and all five original inputs remain identical. A second barrier-based test proves two cases still run together when the configured limit is four and retains a deliberate failed case/error/traceback. The focused saved-replay suite passed 35 tests. The fresh complete isolated suite passed 1004 tests with 1 deselected in 108.97 seconds. RED/GREEN/full-suite logs are preserved without edits.

All work was isolated and offline. No model/network calls, installation, shared-harness writes, main-workspace edits or process control were performed. Copied parent product files remain unstaged and excluded from this change.
